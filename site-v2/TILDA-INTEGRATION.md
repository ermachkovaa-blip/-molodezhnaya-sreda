# Tilda-интеграция V2 — черновик (Этап 1)

Этот файл фиксирует состояние Tilda-готовности модуля на Этапе 1 (shell
без локальных интерактивов зон). Будет дополняться на каждом следующем
этапе; полная версия — не раньше Definition of Done из Production-ТЗ.

## Контракт модуля

Единственная публичная точка входа:

```js
var instance = YHApp.mount(rootEl, config);
```

- `rootEl` — любой элемент, подготовленный интегратором. Модуль не создаёт
  собственных `<html>/<head>/<body>` и не требует, чтобы `rootEl` был
  прямым потомком `<body>`.
- `config.scenes` / `config.links` / `config.uiStrings` — обычные объекты
  (см. `/config/*.js`). Интегратор может передать свои данные без
  изменения кода модуля — это и есть механизм подмены `APPLICATION_URL`
  и других destinations без переписывания зон.
- `instance.unmount()` — снимает все обработчики (ResizeObserver, Pointer
  Events, keydown), ничего не оставляет в `document` за пределами `rootEl`.

## Что уже Tilda-safe на этом этапе

- Один root-контейнер (`.yh-app` — класс, не id, можно смонтировать в
  любой переданный элемент).
- CSS полностью scoped: каждое правило в `app.css` начинается с `.yh-app`.
  Ни одного голого `*`, `html`, `body`, `a`, `button`, `img`.
- `document.body` нигде не используется как обязательная зависимость.
- Debug-режим переключается классом на `rootEl`, а не на `body`.
- `ResizeObserver` на самом контейнере — module пересчитывает камеру и
  desktop/mobile-ветку конфига по реальному размеру `rootEl`, а не по
  размеру окна браузера. Проверено тестом, который меняет размер
  контейнера, не трогая viewport (`tests/shell.spec.js`).
- Pointer Events + `setPointerCapture` — единый код для мыши/тача/пера,
  без раздельных mouse/touch-веток.
- Клавиша `M` слушается на `rootEl`, не на `document` — не перехватывает
  горячие клавиши остальной Tilda-страницы.
- `APPLICATION_URL` — единственное поле, отвечающее за адрес CTA во всех
  зонах; замена значения не требует правок в `core/*` или `config/scenes.js`.

## Известные ограничения ЭТОГО этапа (не готово к продакшн-embed)

- **`config/scenes.js` использует относительные пути к assets**
  (`../../assets/scenes/...`), которые рассчитаны на конкретное
  расположение файла, загружающего скрипты (`/site-v2/embed/demo.html`).
  Это ломается, если модуль подключат с другого пути/домена. До реальной
  Tilda-интеграции это поле должно стать параметром (`config.assetsBaseUrl`
  или абсолютные URL хостинга) — сознательно отложено, чтобы не усложнять
  shell раньше времени.
- **Прямой DOM-embed (без iframe) ни разу не проверялся на настоящей
  странице Tilda** — только на локальной demo-странице с чистым
  `document`. Тест "CSS не течёт наружу" (`tests/shell.spec.js`, describe
  "Tilda-safety") проверяет принцип на синтетическом соседнем элементе, но
  не гарантирует отсутствие конфликтов с реальными, часто очень
  специфичными правилами тем Tilda (`.t-*`, `.t396-*`, `.tn-*`) — это
  можно закрыть только реальным embed-тестом, запланированным на более
  поздний этап (после того как в модуле появится что встраивать, кроме
  shell).
- **`?debug=1` читается только в `embed/demo.html`**, не в `mount()` —
  осознанно: query-параметр не всегда предсказуемо доступен внутри embed.
  Debug включается через `config.debug`, а `demo.html` — лишь один из
  примеров, как проброс из URL можно организовать снаружи модуля.
- **Локальных интерактивов зон ещё нет** — соответственно, ещё не
  проверено, как второй/третий слой z-index (hotspots, drawers, viewer)
  будет вести себя внутри реальной Tilda-темы. Токены заложены
  (`--yh-z-*` в `app.css`), но не все уровни ещё используются.
- **CTA сейчас указывает на `../apply.html` (V1)** — временный, реально
  рабочий prototype-destination для проверки кликабельности на этом этапе;
  собственная форма V2 и/или Tilda-destination подставляются позже без
  изменений в `core/global-nav.js`.

## Варианты подключения (предварительно, будет уточнено)

Как и для V1 (см. ранее переданный `Tilda-integration-guide.docx`),
ожидаются те же два пути:

1. **iframe на внешний хостинг** — самый низкорисковый, полная CSS/DOM-
   изоляция бесплатно. Подходит уже сейчас для демонстрации shell.
2. **Прямой embed** (`mount()` в DOM самой Tilda-страницы, без iframe) —
   именно ради этого написан весь раздел "Что уже Tilda-safe" выше;
   требует итогового прогона на реальной Tilda-странице перед приёмкой.

Полная версия этого файла (пошаговая инструкция, конкретный код для
Zero Block, чек-лист) будет дописана на этапе, отведённом под Tilda-
интеграцию в implementation plan — раньше времени фиксировать шаги
означало бы описывать то, что ещё не проверено на практике.
